🟢 SECTION 2: WHAT ARE HOOKS IN REACT?
==============================================================================
Hooks are special functions that allow you to "hook into" React state and
component lifecycle features inside functional components without classes.

✨ All hook names begin with the prefix "use".

------------------------------------------------------------------------------
⚡ THE ESSENTIAL HOOKS CHEAT SHEET:
------------------------------------------------------------------------------

🔸 1. useState
   • Purpose : Creates local reactive state for your component.
   • Behavior: Updating state triggers an immediate re-render with new data.
   • Example (frontend/src/app/App.tsx):
       const [cart, setCart] = useState<Cart | null>(null);
       const [isCartOpen, setIsCartOpen] = useState<boolean>(false);

🔸 2. useEffect
   • Purpose : Handles asynchronous operations and side effects:
               - Fetching API data
               - Setting up event listeners or timers
               - Direct DOM interactions
   • Dependency Array Rules:
       []         -> Runs ONCE when component mounts.
       [cart]     -> Runs whenever the "cart" variable changes.
       (none)     -> Runs on EVERY single re-render.
   • Example (frontend/src/app/App.tsx):
       useEffect(() => {
         refreshCart();
       }, []);

🔸 3. useContext
   • Purpose : Reads data from a React Context directly.
   • Benefit : Avoids "prop drilling" (passing data through 5 levels of props).
   • Example : Reading global theme, user auth token, or shopping cart.

🔸 4. useRef
   • Purpose : Holds a mutable value that stays constant across renders
               WITHOUT triggering a re-render when changed.
   • Also used to access DOM elements directly (e.g. inputRef.current.focus()).

🔸 5. useMemo
   • Purpose : Performance optimization. Caches the result of an expensive
               calculation between re-renders until dependencies change.

🔸 6. useCallback
   • Purpose : Performance optimization. Caches a function definition
               between re-renders to prevent unnecessary child re-renders.


==============================================================================
🔴 SECTION 3: THE 2 GOLDEN RULES OF HOOKS
==============================================================================

  ⛔ RULE #1: ONLY CALL HOOKS AT THE TOP LEVEL
     • Never call hooks inside loops (for, while), conditional checks (if/else),
       or nested callback functions.
     • Always declare them at the very top of your React component.

  ⛔ RULE #2: ONLY CALL HOOKS FROM REACT FUNCTIONS
     • Call hooks from React functional components.
     • Call hooks from custom hooks (functions starting with 'use...').
     • NEVER call hooks inside standard vanilla JavaScript helper functions.

🔵 SECTION 4: WHAT DOES "import ReactDOM from 'react-dom/client';" MEAN?
==============================================================================
Location: 📁 frontend/src/main.tsx (Line 4)

  import ReactDOM from 'react-dom/client';

  ReactDOM.createRoot(document.getElementById('root') as HTMLElement).render(
    <React.StrictMode>
      <App />
    </React.StrictMode>
  );

🔹 1. THE ARCHITECT vs. THE BUILDER:
   - React is the ARCHITECT: It creates virtual components (<App />), manages
     state, and creates the Virtual DOM blueprint. It does NOT know how to
     paint real pixels onto a web browser.
   - ReactDOM is the BUILDER: It takes the virtual blueprint and translates
     it into real HTML DOM nodes (<div>, <h1>, <button>) inside the browser.

🔹 2. WHY '/client'?
   - React 18 introduced modern Concurrent rendering and separated client
     browser rendering ('react-dom/client') from server-side rendering
     ('react-dom/server').

🔹 3. WHAT DOES createRoot() DO?
   - document.getElementById('root'): Finds <div id="root"></div> in index.html.
   - ReactDOM.createRoot(): Designates that container as the React 18 root.
   - .render(<App />): Physically mounts and paints the React application.

🚀 SECTION 7: WHAT DOES "createRoot(...).render(...)" MEAN?
==============================================================================
Location: 📁 frontend/src/main.tsx (Lines 8-12)

  ReactDOM.createRoot(document.getElementById('root') as HTMLElement).render(
    <React.StrictMode>
      <App />
    </React.StrictMode>
  );

⚡ THE STORY OF THE FOUNDATION, SAFETY INSPECTOR & POWER SWITCH:
   1. Finding the Land (document.getElementById('root')):
      Searches index.html to find the single empty div: <div id="root"></div>.
   2. The Deed Guarantee (as HTMLElement):
      TypeScript worries: "What if this element doesn't exist and returns null?"
      By writing 'as HTMLElement', you sign a guarantee that the element exists.
   3. Pouring Concrete (ReactDOM.createRoot(...)):
      Hands the container over to React 18, setting up the Concurrent Engine,
      Fiber state tree, and scheduling queue.
   4. The Safety Inspector (<React.StrictMode>):
      A development watchdog that inspects the building before opening.
      It double-runs effects and component lifecycles in dev mode to detect
      memory leaks, obsolete methods, and unhandled side effects.
   5. Flipping the Master Switch (.render(<App />)):
      Ignites the entire application, mounting the Master Castle (<App />)
      and streaming real reactive HTML elements to the user's screen!

🔹 3 KEY TAKEAWAYS:
   1. React 18 Concurrent Mode: createRoot replaces the old legacy
      ReactDOM.render(), enabling smoother transitions and batched updates.
   2. StrictMode Console Logs: If console.log prints twice in dev mode,
      StrictMode is verifying your cleanup logic. It only runs once in production.
   3. Total Ignition: Without this 5-line block, all your React code remains
      just dormant JavaScript in memory without painting anything to the DOM.

  import { BrowserRouter, Routes, Route } from 'react-router-dom';

📖 THE STORY OF THE GRAND RAILWAY:
  In ancient websites (1990s), whenever a customer clicked a link to view a
  product, the entire page collapsed, the browser screen flashed blank white,
  and the entire castle had to be rebuilt from scratch over the network.
  react-router-dom brings the high-speed bullet railway system:
  1. BrowserRouter (The Grand Railway Station): Controls the browser's URL bar
     and history stack without ever refreshing or blinking the screen.
  2. Routes (The Master Switch Operator): Looks at the incoming passenger's ticket
     (the URL) and switches the track to the correct destination platform.
  3. Route (The Destination Platform): Defines where the train stops:
     - URL "/"           --> Platform: HomePage
     - URL "/search"     --> Platform: SearchPage
     - URL "/checkout"   --> Platform: CheckoutPage

🔹 DEFINITION:
  Client-Side Routing library for Single Page Applications (SPAs). It intercepts
  URL changes and instantly swaps components in memory with 0ms page reloads.

💡 PRACTICAL EXAMPLE:
  <Routes>
    <Route path="/about" element={<AboutPage />} />
  </Routes>

🟢 POINT 2.7: LINES 17–28 — THE MORNING BELL & LEDGER SYNCHRONIZATION
==============================================================================
Code:
  const refreshCart = async () => {
    try {
      const c = await api.getCart();
      setCart(c);
    } catch (err) {
      console.error('Failed to sync cart:', err);
    }
  };

  useEffect(() => {
    refreshCart();
  }, []);

📖 THE STORY OF THE MORNING BELL:
  When a shopper walks through the store entrance, they might already have
  reserved items from a previous visit stored in server session cookies.
  1. refreshCart(): The store clerk immediately sends the diplomatic courier
     (await api.getCart()) to check the ledger in the Go backend.
     When the courier returns, setCart(c) fills the local cart vault.
     If the server is unreachable, the 'catch' block gracefully logs the error
     without crashing the customer's browser.
  2. useEffect(..., []): The empty array '[]' is the Golden Rule of the Morning Bell!
     It commands React: "Ring this bell and fetch the cart exactly ONCE when the
     store first opens (component mounts). Do NOT ring it again on normal re-renders!"

🔹 DEFINITION:
  Mount lifecycle side-effect in React. An empty dependency array '[]' guarantees
  the asynchronous data-fetching function executes only once after initial render.

🔴 POINT 2.8: LINES 30–56 — THE THREE TRUSTED STORE CLERKS
==============================================================================
Code:
  // Clerk 1: Add item and pop open the cart drawer
  const handleAddToCart = async (variantId: string, quantity: number = 1) => {
    const updated = await api.addToCart(variantId, quantity);
    setCart(updated);
    setIsCartOpen(true);
  };

  // Clerk 2: Update item quantity (+ / - / delete)
  const handleUpdateQuantity = async (cartItemId: string, quantity: number) => {
    const updated = await api.updateCartItem(cartItemId, quantity);
    setCart(updated);
  };

  // Clerk 3: Validate and apply promotional coupons
  const handleApplyCoupon = async (code: string) => {
    try {
      const updated = await api.applyCoupon(code);
      setCart(updated);
    } catch (err: any) {
      alert(err.message || 'Invalid coupon');
    }
  };

📖 THE STORY OF THE THREE CLERKS:
  Whenever a customer interacts with products, three specialized clerks handle it:
  1. Clerk 1 (handleAddToCart): Takes the item ID and desired quantity, calls
     the Go backend, updates the cart vault (setCart), and immediately slides
     the cart drawer open (setIsCartOpen(true)) so the customer gets instant,
     satisfying visual feedback that their item was safely captured!
  2. Clerk 2 (handleUpdateQuantity): Manages the quantity selector inside the drawer.
     Whether the customer clicks '+' to buy another or sets quantity to 0 to remove it,
     this clerk synchronizes the new counts with the server and updates state.
  3. Clerk 3 (handleApplyCoupon): Takes promo discount codes (like 'SUMMER20').
     It attempts to apply the code against backend discount rules.
     If valid, the new discounted total is saved; if invalid or expired, it intercepts
     the error safely and shows an alert dialog ('Invalid coupon').

🔹 DEFINITION:
  Higher-order asynchronous business logic handlers passed down via props
  to child components to trigger centralized state mutations.
