1. APPLICATION & DATABASE OVERVIEW
--------------------------------------------------------------------------------
Application Name : StyleHome (Atelier Living & Architectural Furniture)
Database Name    : Eshop (PostgreSQL 16 Multi-Schema Cluster)
Architecture     : Domain-Driven Design (DDD) + Event-Driven Microservices + CQRS
Backend Engine   : Go 1.26 (Standard Library net/http + gRPC Protobuf, Zero Frameworks)
Frontend Engine  : React 18 SPA (TypeScript + Vite + React Router + React Query)
Search Engine    : Elasticsearch 8.x (BM25 Full-Text + Edge N-Gram Autocomplete + Facets)
In-Memory Store  : Redis 7.x (Token-Bucket Rate Limiter, Live Carts, Idempotency Keys)
Messaging Bus    : Apache Kafka + Schema Registry + Transactional Outbox Pattern

================================================================================
2. TECHNOLOGY STACK & ARCHITECTURAL BENEFITS
================================================================================

A. Go Standard Library (net/http) Without Frameworks:
   - Eliminates third-party dependency deprecation and framework churn.
   - Leverages Go's built-in HTTP server and lightweight goroutine-per-connection.
   - Composable middleware pipeline: func(http.Handler) http.Handler for RequestID,
     Structured Logger, Panic Recovery, CORS, Rate Limiting, and JWT extraction.

B. gRPC / Protobuf v3:
   - High-throughput binary protocol over HTTP/2 with multiplexing and header compression.
   - Sub-millisecond synchronous communication for critical paths (Checkout -> Payment,
     Cart -> Inventory Stock Checks).

C. GraphQL BFF (Backend-For-Frontend):
   - Schema-first design (SDL) aggregating Catalog, Real-Time Stock, Cart, and Orders.
   - Eliminates over-fetching and under-fetching by resolving multi-service queries in
     a single client roundtrip.

D. CQRS (Command Query Responsibility Segregation):
   - Command Path (Write): Handled with PostgreSQL row locks, ACID invariants, and
     Distributed Saga Orchestration.
   - Query Path (Read): Fast lookups served from Redis caches and Elasticsearch indices.

E. Elasticsearch:
   - Edge n-gram tokenizers for real-time search autocomplete.
   - Dynamic faceted aggregations for brands, categories, and price ranges.

F. Apache Kafka & Transactional Outbox:
   - Outbox table commits domain events atomically with business transactions in PostgreSQL.
   - Asynchronous worker dispatches events (OrderPlaced, PaymentCaptured) to Kafka,
     ensuring zero event loss even during network partitions or crashes.

4. COMMANDS TO RUN, BUILD, TEST, AND DEPLOY
================================================================================

A. RUNNING LOCALLY (Native Mode):

   1. Run Backend Server (Go net/http on :8080):
      $ go run ./cmd/bff-server

   2. Run Frontend Dev Server (Vite on :3000):
      $ cd frontend
      $ npm install
      $ npm run dev

   3. Endpoints available:
      - React UI        : http://localhost:3000
      - GraphQL BFF     : http://localhost:8080/graphql
      - Health Probe    : http://localhost:8080/healthz
      - Payment Webhook : http://localhost:8080/api/webhooks/payment

B. RUNNING WITH DOCKER COMPOSE:

   1. Start all services (Postgres Eshop DB, Elasticsearch, Redis, Kafka, Backend):
      $ docker-compose up --build

   2. Stop all services:
      $ docker-compose down

C. BUILDING PRODUCTION BINARIES:

   1. Build Go Backend Binary:
      $ go build -ldflags="-w -s" -o bff-server.exe ./cmd/bff-server

   2. Build React Frontend Production Bundle:
      $ cd frontend
      $ npm run build

D. RUNNING TESTS:

   1. Run Go Unit & Integration Tests:
      $ go test ./...

   2. Run Static Analysis:
      $ go vet ./...
