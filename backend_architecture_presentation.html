Slide 02 • Core HTTP Engine

Pure Go Standard Library (Zero-Frameworks)

Why we opted out of Gin/Fiber/Echo in favor of standard net/http and composable middleware.

🛡️ Strategic Architectural Benefits

  • Zero Dependency Deprecation Risk: Go's net/http API has maintained strict backward compatibility for over 10 years without breaking changes.
  • Idiomatic Middleware Chaining: Built using type Middleware func(http.Handler) http.Handler.
  • Request ID Propagation: Injects 16-byte cryptographically random trace IDs into context.Context and HTTP response headers.
  • Built-In Concurrency: Native goroutine-per-connection scaling without thread contention or external event loops.
internal/pkg/middleware/middleware.go 
type Middleware func(http.Handler) http.Handler

// Chain aggregates multiple middlewares and executes left-to-right
func Chain(middlewares ...Middleware) Middleware {
    return func(final http.Handler) http.Handler {
        for i := len(middlewares) - 1; i >= 0; i-- {
            final = middlewares[i](final)
        }
        return final
    }
}

// RequestID middleware with cryptographically secure trace IDs
func RequestID() Middleware {
    return func(next http.Handler) http.Handler {
        return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
            reqID := r.Header.Get("X-Request-ID")
            if reqID == "" {
                bytes := make([]byte, 16)
                _, _ = rand.Read(bytes)
                reqID = hex.EncodeToString(bytes)
            }
            w.Header().Set("X-Request-ID", reqID)
            ctx := context.WithValue(r.Context(), RequestIDKey, reqID)
            next.ServeHTTP(w, r.WithContext(ctx))
        })
    }
}
Slide 03 • API Layer

GraphQL BFF & Fan-Out / Fan-In Resolvers

Accelerating initial load latency by resolving catalog, categories, and carts concurrently.

⚡ Parallelism with sync.WaitGroup

  • Eliminates Over/Under-Fetching: Single roundtrip query aggregates Catalog, Stock, Cart, and User profiles.
  • Fan-Out / Fan-In Execution: Instead of serial execution (T1 + T2 + T3 = 150ms), three goroutines run in parallel.
  • 66% Latency Reduction: Overall page aggregation latency drops to max(T1, T2, T3) ≈ 50ms.
  • Context Propagation: Every sub-goroutine inherits the client's request context for automated cancellation.

    var prods []*catalogDomain.Product
    var cats  []*catalogDomain.Category
    var cart  *cartDomain.Cart

    wg.Add(3)

    go func() {
        defer wg.Done()
        prods = h.catalogSvc.ListAllProducts(ctx)
    }()

    // Goroutine 2: Fetch Categories
    go func() {
        defer wg.Done()
        cats = h.catalogSvc.ListCategories(ctx)
    }()

    go func() {
        defer wg.Done()
        cart = h.cartSvc.GetOrCreateCart(ctx, sessionID, userID != "")
    }()

Slide 04 • Distributed Transactions

Order Placement Saga Orchestrator

Replacing heavy Two-Phase Commit (2PC) with Orchestrated Sagas and automated compensating rollbacks.

🔄 5-Stage Distributed Transaction

  • Step 1 (Stock Hold): Inventory service reserves items with a 15-minute TTL hold.
  • Step 2 (Payment Auth): Idempotent payment gateway authorization via gRPC.
  • Compensating Rollback: If payment fails or gateway errors, the saga triggers ReleaseReservation to unblock inventory immediately.
  • Step 3 (Commit & Confirm): On payment success, order is persisted to PostgreSQL and stock reservations committed.

if err != nil || !resResult.Success {

Slide 05 • Event Streaming

Transactional Outbox Pattern & Apache Kafka

Guaranteeing zero event loss across network failures and broker outages.

📦 Why Not Dual-Writes?

  • The Dual-Write Problem: Writing to PostgreSQL and Kafka directly from an HTTP handler leads to inconsistent states if Kafka goes down mid-flight.
  • Atomic DB Commit: The outbox_events table is updated within the exact same ACID transaction as the order.
  • Asynchronous Streaming: Dedicated Go background worker polls the outbox and streams events to Kafka brokers.
  • At-Least-Once Delivery: Guarantees event delivery to downstream consumers (Notifications, Analytics, Inventory Sync).
internal/pkg/outbox/publisher.go 
func (w *Worker) Start(ctx context.Context) {
    ticker := time.NewTicker(500 * time.Millisecond)

    go func() {
        for {
            select {
            case <-ctx.Done():
                ticker.Stop()
                return
            case <-ticker.C:
                w.dispatchUnpublishedEvents(ctx)
            }
        }
    }()
}

func (w *Worker) dispatchUnpublishedEvents(ctx context.Context) {
    w.mu.Lock()
    defer w.mu.Unlock()

    for i := range w.records {
        if !w.records[i].Published {
            if err := w.publisher.Publish(ctx, w.records[i]); err == nil {
                w.records[i].Published = true
                w.records[i].PublishedAt = time.Now()
            }
        }
    }
}
Slide 06 • Concurrency Mechanics

Inventory Reservation & Background Reaper

Non-blocking background cleanups via Go time.Ticker and sync.RWMutex.

⏱️ Automatic Stock Recovery

  • Flash-Sale Protection: When users add items to checkout, stock is locked using sync.RWMutex.
  • Cart Abandonment Problem: Users close tabs or lose connection with items held in reservations.
  • Go Periodic Reaper: Dedicated goroutine fires every 30s using time.Ticker + select.
  • Safe Concurrency: Locks only expired reservations and restores inventory balances without deadlocks.
internal/inventory/service/inventory_service.go 
func (s *Service) startBackgroundReservationReaper(ctx context.Context) {
    ticker := time.NewTicker(30 * time.Second)

    go func() {
        for {
            select {
            case <-ctx.Done():
                ticker.Stop()
                return
            case <-s.stopChan:
                ticker.Stop()
                return
            case <-ticker.C:
                s.reapExpiredReservations()
            }
        }
    }()
}

func (s *Service) reapExpiredReservations() {
    s.mu.Lock()
    defer s.mu.Unlock()
    now := time.Now()

    for resID, res := range s.reservations {
        if res.Status == domain.ReservationPending && now.After(res.ExpiresAt) {
            // Release held quantities back to available pool
            res.Status = domain.ReservationReleased
            s.stocks[res.SKU].ReservedQuantity -= res.Quantity
        }
    }
}
Slide 07 • Persistence Layer

PostgreSQL 16 Multi-Schema DDD & Connection Pool

Standard Library database/sql connection pooling configured for high concurrency.

🗄️ Domain Isolation & Pool Tuning

  • Target Database: Eshop cluster with isolated SQL schemas (auth_schema, catalog_schema, order_schema, inventory_schema).
  • Driver Neutrality: Works with pure Go drivers without ORM reflection overhead.
  • Tuned Connection Limits:
    • MaxOpenConns: 50 (burst prevention)
    • MaxIdleConns: 25 (pre-warmed connections)
    • ConnMaxLifetime: 30m (connection rotation)
  • Context Cancellation: Context timeout prevents orphaned database queries on client disconnect.
internal/pkg/database/postgres.go 
func Connect(ctx context.Context, cfg Config) (*DB, error) {
    db, err := sql.Open("pgx", cfg.URL)
    if err != nil {
        return nil, fmt.Errorf("failed to open pool: %w", err)
    }

    // High throughput pool limits
    db.SetMaxOpenConns(cfg.MaxOpenConns)       // 50
    db.SetMaxIdleConns(cfg.MaxIdleConns)       // 25
    db.SetConnMaxLifetime(cfg.ConnMaxLifetime) // 30 min
    db.SetConnMaxIdleTime(cfg.ConnMaxIdleTime) // 5 min

    // Health check with strict timeout
    pingCtx, cancel := context.WithTimeout(ctx, 3*time.Second)
    defer cancel()

    if err := db.PingContext(pingCtx); err != nil {
        log.Printf("[DATABASE WARNING] Eshop ping fallback: %v", err)
    }

    return &DB{DB: db}, nil
}
