1. EXECUTIVE ARCHITECTURE SUMMARY & TECHNOLOGY SELECTION
================================================================================

StyleHome is an enterprise-grade, high-concurrency e-commerce platform built to
support millions of users, high-velocity flash-sales, and sub-second discovery.

Technology Selection Rationale & Benefits:

1. Go Standard Library (net/http) Without Third-Party Frameworks:
   - Eliminates framework churn, breaking changes, and heavy dependency trees.
   - Operates on Go's lightweight runtime scheduler (goroutines per connection).
   - Composable middleware pipeline: func(http.Handler) http.Handler for RequestID,
     Structured Logger, Panic Recovery, CORS, Rate Limiting, and JWT extraction.

2. gRPC over HTTP/2 (Protobuf v3):
   - High-throughput binary protocol with multiplexing and header compression.
   - Strictly-typed schema definitions with backward/forward compatibility.
   - Eliminates JSON serialization bottlenecks in internal service-to-service calls
     (e.g., Cart -> Inventory Stock Verification, Checkout -> Payment Auth).

3. GraphQL BFF (Backend-For-Frontend):
   - Single unified endpoint for the React SPA.
   - Resolves multi-service aggregates (Catalog + Real-Time Stock + Cart + Discounts)
     in a single round-trip, preventing over-fetching and under-fetching.

4. CQRS (Command Query Responsibility Segregation):
   - Command Path (Write): Handled with PostgreSQL row locks, ACID invariants, and
     Distributed Saga Orchestration.
   - Query Path (Read): Fast lookups served from Redis caches and Elasticsearch indices.

5. Elasticsearch Inverted Index & Edge N-Grams:
   - Real-time search autocomplete as users type.
   - Sub-10ms response times for faceted filtering (Brand, Category, Price brackets).

6. Apache Kafka & Transactional Outbox Pattern:
   - Outbox table commits domain events atomically with business transactions in PostgreSQL.
   - Asynchronous worker dispatches events (OrderPlaced, PaymentCaptured) to Kafka,
     ensuring zero event loss even during network partitions or crashes.

7. PostgreSQL (Eshop Database):
   - Primary transactional database providing ACID guarantees for orders, payments,
     and stock ledgers with schema-per-service isolation.

8. Redis:
   - In-memory accelerator for guest cart sessions, distributed locks, rate limiting,
     and 24-hour idempotency key validation.

3. MICROSERVICES DIRECTORY & STORAGE OWNERSHIP
================================================================================

1. Auth & Identity Service:
   - Responsibilities: Registration, OAuth2/OIDC, JWT issuance, RBAC, MFA.
   - Data Stores: PostgreSQL (auth_schema), Redis (Token Blacklist).

2. User Profile Service:
   - Responsibilities: Customer addresses, preferences, saved payment tokens.
   - Data Stores: PostgreSQL (auth_schema).

3. Catalog Service:
   - Responsibilities: Product hierarchy, categories, variants, SKUs, images.
   - Data Stores: PostgreSQL (catalog_schema), Redis (Hot Product Cache), S3.

4. Search & Discovery Service:
   - Responsibilities: Full-text search, faceted navigation, autocomplete.
   - Data Stores: Elasticsearch (product_catalog index).

5. Cart & Session Service:
   - Responsibilities: Persistent user carts, guest sessions, price calculations.
   - Data Stores: Redis (Active carts), PostgreSQL (cart_schema).

6. Checkout & Promotion Service:
   - Responsibilities: Coupon rules, multi-step validation, tax/shipping.
   - Data Stores: PostgreSQL (promotion_schema), Redis (Promo Rules).

7. Orders Service (CQRS):
   - Responsibilities: Order lifecycle, CQRS commands, state machine, outbox events.
   - Data Stores: PostgreSQL (order_schema + outbox), Redis.

8. Payment Service (CQRS):
   - Responsibilities: Payment gateway orchestration, captures, refunds.
   - Data Stores: PostgreSQL (payment_schema + outbox).

9. Inventory Service (CQRS):
   - Responsibilities: Stock reservation with TTL, warehouse ledger, backorder rules.
   - Data Stores: PostgreSQL (inventory_schema), Redis (Distributed Locks).

10. Notification Service:
   - Responsibilities: Email (SES/SendGrid), SMS (Twilio), Web Push.
   - Data Stores: PostgreSQL (notification_logs).

--- Inventory Service (proto/inventory/v1/inventory.proto) ---
syntax = "proto3";
package inventory.v1;
option go_package = "github.com/stylehome/eshop/proto/inventory/v1;inventoryv1";

service InventoryService {
  rpc CheckStock (CheckStockRequest) returns (CheckStockResponse);
  rpc ReserveStock (ReserveStockRequest) returns (ReserveStockResponse);
  rpc CommitReservation (CommitReservationRequest) returns (CommitReservationResponse);
  rpc ReleaseReservation (ReleaseReservationRequest) returns (ReleaseReservationResponse);
}

message ReserveItem { string sku = 1; int32 quantity = 2; }
message ReserveStockRequest {
  string order_id = 1;
  string idempotency_key = 2;
  repeated ReserveItem items = 3;
  int32 hold_duration_seconds = 4;
}
message ReserveStockResponse {
  bool success = 1;
  string reservation_id = 2;
  repeated string out_of_stock_skus = 5;
}

--- Payment Service (proto/payment/v1/payment.proto) ---
syntax = "proto3";
package payment.v1;
option go_package = "github.com/stylehome/eshop/proto/payment/v1;paymentv1";

service PaymentService {
  rpc AuthorizePayment (AuthorizePaymentRequest) returns (AuthorizePaymentResponse);
  rpc CapturePayment (CapturePaymentRequest) returns (CapturePaymentResponse);
  rpc RefundPayment (RefundPaymentRequest) returns (RefundPaymentResponse);
}

message Money { int64 amount_in_cents = 1; string currency = 2; }
message AuthorizePaymentRequest {
  string order_id = 1;
  string user_id = 2;
  Money amount = 3;
  string payment_token = 5;
  string idempotency_key = 6;
}

-- Transactional Outbox Pattern Table (Zero Event Loss Guarantee)
CREATE TABLE IF NOT EXISTS order_schema.outbox_events (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    aggregate_type VARCHAR(100) NOT NULL, -- 'ORDER'
    aggregate_id VARCHAR(255) NOT NULL,   -- order_id
    event_type VARCHAR(100) NOT NULL,     -- 'OrderPlaced', 'OrderCancelled'
    payload JSONB NOT NULL,
    published BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
